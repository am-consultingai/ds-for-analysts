# Churn model · project rules
Claude reads this file at the start of every session.

## The question
Rank accounts by risk of churning in the 90 days after the cutoff.
The CSM team acts on the top 10 each week.

## Rules
- Label: no renewal, or contraction below threshold, within 90 days
- Cutoff 2026-01-01. Features use data from before it only.
- Split by time. Never at random.
- Baseline: today's CSM rule. Every model must beat it.
- random_state=0 everywhere.
- Report train and test scores. Print row counts at every step.
- Never print raw customer rows.
import pandas as pd

CUTOFF = pd.Timestamp("2026-01-01")          # the day the prediction is made

events = pd.read_parquet("product_events.parquet")
events = events[events.ts < CUTOFF]          # nothing after the cutoff. ever.

features = (
    events
    .groupby("account_id")
    .agg(
        logins_last_30d=("ts", lambda s: (s > CUTOFF - pd.Timedelta("30D")).sum()),
        media_sources_count=("media_source", "nunique"),
        support_tickets_open=("ticket_open", "sum"),
    )
    .reset_index()
)
from xgboost import XGBClassifier

Common questions

Do they need to know Python?
No. Claude writes the code. They learn to read it well enough to check it.
Why Claude Code?
It writes and runs the code, and follows your project rules. The result is plain Python that your BI team can use.
Why XGBoost and not deep learning?
On business data, XGBoost usually wins. Deep learning is best for images, text and very large data.
What are the workshop skills?
Ready-made instructions that Claude follows for each step: data check, features, training and testing. Your analysts keep them.
Will anything go to production?
Not in the workshop. We show how it works. Your BI team does it later.
How do we keep going after the workshop?
Each analyst leaves with a plan. A follow-up session a few weeks later helps most.
Hebrew or English?
Materials are in English. Teaching can be in either.
